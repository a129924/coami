# Scope Draft Plan checklist

Use this before presenting the Draft Plan.

- [ ] The task is scope convergence, not direct implementation, a full
  implementation plan, or a bounded bug fix.
- [ ] The recommendation is one business capability, not a technical layer.
- [ ] A primary BC, actor, core result, and ownership story are explicit.
- [ ] The Mission has an end-to-end happy path and essential failure path.
- [ ] In Scope contains only behavior needed for that result.
- [ ] Out of Scope names independently valuable outcomes and unowned cross-BC
  work.
- [ ] Repository, DTO, database, service, API, and tests remain technical tasks
  in one Mission.
- [ ] Acceptance criteria are observable and implementation-independent.
- [ ] Cross-BC dependencies are contracts or dependent Missions, not silently
  absorbed work.
- [ ] Material uncertainty caused at most three focused questions; lower-impact
  uncertainty is declared as an assumption.
- [ ] The output follows the localizable template and is Traditional Chinese by
  default when no other language governs.
- [ ] Any next-step guidance is conditional and non-binding.
- [ ] The response does not write artifacts, dispatch agents, invoke skills,
  create an implementation plan, or claim approval.
